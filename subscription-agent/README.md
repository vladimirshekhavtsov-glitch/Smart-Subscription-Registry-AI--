# Smart Subscription Registry — AI-агент для учёта подписок

ReAct-агент на LangChain, который отвечает на вопросы о личных подписках и
регулярных платежах на естественном языке, вызывая инструменты для чтения
данных пользователя и конвертации валют.

## Архитектура

```
app/
├── data/obligations.json  # фикстура: 15 обязательств пользователя
├── tools_core.py           # чистая бизнес-логика (без LangChain) — легко тестировать
├── tools.py                 # обёртки над tools_core в виде LangChain StructuredTool
├── agent.py                  # сборка ReAct-агента (create_tool_calling_agent + AgentExecutor)
├── logging_callback.py        # консольный трейс Thought/Action через callbacks
└── main.py                     # CLI: интерактивный режим и одноразовый вопрос
tests/
└── test_tools_core.py    # 11 unit-тестов на оба инструмента
```

## Как запустить

### Вариант 1 — Docker (рекомендуется, из задания)

```bash
cp .env.example .env
# впишите в .env свой GROQ_API_KEY (бесплатный ключ: https://console.groq.com/keys)

docker compose up            # интерактивный режим (вопрос-ответ в консоли)
# или одноразовый вопрос без интерактивного терминала:
docker compose run --rm agent "Сколько я потрачу в ближайшие 30 дней? Покажи итог в рублях."
```

### Вариант 2 — локально

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впишите GROQ_API_KEY

python -m app.main "Какая категория обходится мне дороже всего?"
# или без аргумента — интерактивный режим
python -m app.main
```

### Тесты

```bash
pytest
# либо, без установки pytest:
python -m unittest discover -s tests
```

## Какая LLM выбрана и почему

По умолчанию используется **Groq (`llama-3.3-70b-versatile`)** через
`langchain-groq` (`ChatGroq`). Причины:

- **Бесплатно и быстро.** У Groq щедрый бесплатный тариф и собственное
  инференс-железо (LPU), поэтому ответы приходят заметно быстрее, чем у
  большинства hosted-API — удобно для тестового задания без бюджета на LLM
  и для живой демонстрации трейса рассуждений.
- **Достаточно надёжный native tool-calling.** У инструментов несколько
  параметров (`get_obligations(status, category)`,
  `convert_currency(amount, from_currency, to_currency)`), поэтому важна
  модель, которая умеет function calling, а не только текстовый ReAct с
  ручным парсингом JSON-blob. Из моделей, доступных на бесплатном тарифе
  Groq, `llama-3.3-70b-versatile` показывает наиболее стабильные
  структурированные вызовы инструментов — более мелкие/быстрые модели
  (например, `llama-3.1-8b-instant`) иногда некорректно формируют
  аргументы у многопараметрических вызовов.


## Пример полного ReAct-трейса

Ниже — трейс для запроса **«Сколько я потрачу в ближайшие 30 дней? Покажи
итог в рублях.»** (дата запроса: 2026-07-08, диапазон — по 2026-08-07).
Точные формулировки модели и текущий курс валют будут немного отличаться
при реальном запуске (курс frankfurter.dev обновляется ежедневно) — ниже
показан формат вывода и посчитанные по фикстуре суммы.

```
Question: Сколько я потрачу в ближайшие 30 дней? Покажи итог в рублях.
------------------------------------------------------------
Thought: Сначала нужно получить список активных обязательств пользователя,
чтобы отфильтровать те, у которых next_payment_date попадает в ближайшие
30 дней (с 2026-07-08 по 2026-08-07).
Action: get_obligations
Action Input: {"status": "active"}
Observation: [{"id": "...", "title": "Netflix", "amount": 9.99, "currency": "USD",
"category": "subscription", "next_payment_date": "2026-07-09", "status": "active"},
... ещё 12 записей ...]

Thought: Из 13 активных обязательств в диапазон 2026-07-08–2026-08-07 попадают 11:
в USD (Netflix 9.99, Spotify 5.99, iCloud+ 2.99, Аренда VPS 12.00, Автокредит 220.00,
Adobe CC 54.99 — итого 305.96 USD), в RUB (Яндекс Плюс 399, Интернет 650,
Абонемент в бассейн 3200 — итого 4249 RUB) и в EUR (Фитнес-клуб 45.00,
Курс английского 60.00 — итого 105 EUR). Нужно перевести суммы в USD и EUR в рубли.
Action: convert_currency
Action Input: {"amount": 305.96, "from_currency": "USD", "to_currency": "RUB"}
Observation: {"amount": 305.96, "from_currency": "USD", "to_currency": "RUB", "converted_amount": 27536.40}

Thought: Теперь переведу сумму в евро.
Action: convert_currency
Action Input: {"amount": 105, "from_currency": "EUR", "to_currency": "RUB"}
Observation: {"amount": 105, "from_currency": "EUR", "to_currency": "RUB", "converted_amount": 10290.00}

Thought: Все суммы теперь в рублях: 27536.40 + 10290.00 + 4249.00 = 42075.40 ₽.
Final Answer: В ближайшие 30 дней (08.07–07.08.2026) у вас запланировано 11 платежей
на общую сумму ≈ 42 075.40 ₽ по текущему курсу (USD/RUB ≈ 90, EUR/RUB ≈ 98 на момент
примера). Учтены только активные подписки; приостановленные (Disney+) и отменённые
исключены.
============================================================
FINAL ANSWER: В ближайшие 30 дней (08.07–07.08.2026) у вас запланировано 11 платежей
на общую сумму ≈ 42 075.40 ₽ по текущему курсу (USD/RUB ≈ 90, EUR/RUB ≈ 98 на момент
примера). Учтены только активные подписки; приостановленные (Disney+) и отменённые
исключены.
============================================================
```

## Ограничения

- **Даты считает сама модель.** Фильтрация по «на этой неделе» / «в
  ближайшие 30 дней» — это рассуждение LLM над датами из
  `get_obligations`, а не отдельный инструмент с гарантированно точной
  логикой. На редких edge-cases (например, разные определения «недели»)
  модель может интерпретировать диапазон иначе, чем ожидает пользователь.
- **Курс валют — snapshot на момент запроса.** `frankfurter.dev` даёт
  межбанковский справочный курс, обновляемый раз в день по будням; для
  реальных списаний банк применит свой курс конвертации, который может
  отличаться.
- **Нет памяти между запросами.** Каждый вопрос обрабатывается независимо
  (агент не хранит историю диалога между вызовами `python -m app.main`).
  Это осознанное упрощение — задание не требует многоходовых диалогов.
- **Нет retry/бэкоффа для внешнего API.** При недоступности
  frankfurter.dev агент один раз получает ошибку и честно сообщает об
  этом пользователю (см. `CurrencyConversionError`), вместо повторных
  попыток — это соответствует требованию «не выдумывать данные», но
  означает, что временный сетевой сбой не сглаживается автоматически.
- **Нет валидации ввода на уровне тулов сверх Pydantic-схемы** (например,
  агент технически может передать в `convert_currency` код валюты, не
  поддерживаемый frankfurter.dev — тогда придёт `error` в Observation, и
  агент обязан честно сообщить о невозможности выполнить конвертацию,
  а не придумывать курс).
